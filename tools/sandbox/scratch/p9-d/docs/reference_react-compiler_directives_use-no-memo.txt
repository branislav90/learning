Reference &quot;use no memo&quot; How &quot;use no memo&quot; opts-out of optimization When to use &quot;use no memo&quot; Usage Troubleshooting Directive not preventing compilation Best practices See also Reference &quot;use no memo&quot; Add &quot;use no memo&quot; at the beginning of a function to prevent React Compiler optimization. function MyComponent ( ) { &quot;use no memo&quot; ; // ... } When a function contains &quot;use no memo&quot; , the React Compiler will skip it entirely during optimization. This is useful as a temporary escape hatch when debugging or when dealing with code that doesn’t work correctly with the compiler. Caveats &quot;use no memo&quot; must be at the very beginning of a function body, before any imports or other code (comments are OK). The directive must be written with double or single quotes, not backticks. The directive must exactly match &quot;use no memo&quot; or its alias &quot;use no forget&quot; . This directive takes precedence over all compilation modes and other directives. It’s intended as a temporary debugging tool, not a permanent solution. How &quot;use no memo&quot; opts-out of optimization React Compiler analyzes your code at build time to apply optimizations. &quot;use no memo&quot; creates an explicit boundary that tells the compiler to skip a function entirely. This directive takes precedence over all other settings: In all mode: The function is skipped despite the global setting In infer mode: The function is skipped even if heuristics would optimize it The compiler treats these functions as if the React Compiler wasn’t enabled, leaving them exactly as written. When to use &quot;use no memo&quot; &quot;use no memo&quot; should be used sparingly and temporarily. Common scenarios include: Debugging compiler issues When you suspect the compiler is causing issues, temporarily disable optimization to isolate the problem: function ProblematicComponent ( { data } ) { &quot;use no memo&quot; ; // TODO: Remove after fixing issue #123 // Rules of React violations that weren&#x27;t statically detected // ... } Third-party library integration When integrating with libraries that might not be compatible with the compiler: function ThirdPartyWrapper ( ) { &quot;use no memo&quot; ; useThirdPartyHook ( ) ; // Has side effects that compiler might optimize incorrectly // ... } Usage The &quot;use no memo&quot; directive is placed at the beginning of a function body to prevent React Compiler from optimizing that function: function MyComponent ( ) { &quot;use no memo&quot; ; // Function body } The directive can also be placed at the top of a file to affect all functions in that module: &quot;use no memo&quot; ; // All functions in this file will be skipped by the compiler &quot;use no memo&quot; at the function level overrides the module level directive. Troubleshooting Directive not preventing compilation If &quot;use no memo&quot; isn’t working: // ❌ Wrong - directive after code function Component ( ) { const data = getData ( ) ; &quot;use no memo&quot; ; // Too late! } // ✅ Correct - directive first function Component ( ) { &quot;use no memo&quot; ; const data = getData ( ) ; } Also check: Spelling - must be exactly &quot;use no memo&quot; Quotes - must use single or double quotes, not backticks Best practices Always document why you’re disabling optimization: // ✅ Good - clear explanation and tracking function DataProcessor ( ) { &quot;use no memo&quot; ; // TODO: Remove after fixing rule of react violation // ... } // ❌ Bad - no explanation function Mystery ( ) { &quot;use no memo&quot; ; // ... } See also &quot;use memo&quot; - Opt into compilation React Compiler - Getting started guide Previous &quot;use memo&quot; Next Compiling Libraries Copyright © Meta Platforms, Inc no uwu plz uwu?
