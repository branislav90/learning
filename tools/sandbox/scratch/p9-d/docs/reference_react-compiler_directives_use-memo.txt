marks a function for React Compiler optimization. Note In most cases, you don’t need &quot;use memo&quot; . It’s primarily needed in annotation mode where you must explicitly mark functions for optimization. In infer mode, the compiler automatically detects components and hooks by their naming patterns (PascalCase for components, use prefix for hooks). If a component or hook isn’t being compiled in infer mode, you should fix its naming convention rather than forcing compilation with &quot;use memo&quot; . Reference &quot;use memo&quot; How &quot;use memo&quot; marks functions for optimization When to use &quot;use memo&quot; Usage Working with different compilation modes Troubleshooting Verifying optimization See also Reference &quot;use memo&quot; Add &quot;use memo&quot; at the beginning of a function to mark it for React Compiler optimization. function MyComponent ( ) { &quot;use memo&quot; ; // ... } When a function contains &quot;use memo&quot; , the React Compiler will analyze and optimize it during build time. The compiler will automatically memoize values and components to prevent unnecessary re-computations and re-renders. Caveats &quot;use memo&quot; must be at the very beginning of a function body, before any imports or other code (comments are OK). The directive must be written with double or single quotes, not backticks. The directive must exactly match &quot;use memo&quot; . Only the first directive in a function is processed; additional directives are ignored. The effect of the directive depends on your compilationMode setting. How &quot;use memo&quot; marks functions for optimization In a React app that uses the React Compiler, functions are analyzed at build time to determine if they can be optimized. By default, the compiler automatically infers which components to memoize, but this can depend on your compilationMode setting if you’ve set it. &quot;use memo&quot; explicitly marks a function for optimization, overriding the default behavior: In annotation mode: Only functions with &quot;use memo&quot; are optimized In infer mode: The compiler uses heuristics, but &quot;use memo&quot; forces optimization In all mode: Everything is optimized by default, making &quot;use memo&quot; redundant The directive creates a clear boundary in your codebase between optimized and non-optimized code, giving you fine-grained control over the compilation process. When to use &quot;use memo&quot; You should consider using &quot;use memo&quot; when: You’re using annotation mode In compilationMode: &#x27;annotation&#x27; , the directive is required for any function you want optimized: // ✅ This component will be optimized function OptimizedList ( ) { &quot;use memo&quot; ; // ... } // ❌ This component won&#x27;t be optimized function SimpleWrapper ( ) { // ... } You’re gradually adopting React Compiler Start with annotation mode and selectively optimize stable components: // Start by optimizing leaf components function Button ( { onClick , children } ) { &quot;use memo&quot; ; // ... } // Gradually move up the tree as you verify behavior function ButtonGroup ( { buttons } ) { &quot;use memo&quot; ; // ... } Usage Working with different compilation modes The behavior of &quot;use memo&quot; changes based on your compiler configuration: // babel.config.js module . exports = { plugins : [ [ &#x27;babel-plugin-react-compiler&#x27; , { compilationMode : &#x27;annotation&#x27; // or &#x27;infer&#x27; or &#x27;all&#x27; } ] ] } ; Annotation mode // ✅ Optimized with &quot;use memo&quot; function ProductCard ( { product } ) { &quot;use memo&quot; ; // ... } // ❌ Not optimized (no directive) function ProductList ( { products } ) { // ... } Infer mode (default) // Automatically memoized because this is named like a Component function ComplexDashboard ( { data } ) { // ... } // Skipped: Is not named like a Component function simpleDisplay ( { text } ) { // ... } In infer mode, the compiler automatically detects components and hooks by their naming patterns (PascalCase for components, use prefix for hooks). If a component or hook isn’t being compiled in infer mode, you should fix its naming convention rather than forcing compilation with &quot;use memo&quot; .
