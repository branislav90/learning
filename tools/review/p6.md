## 02 Cancellation and race conditions
- Confirmed (executed in Node 24 against a local server): default `abort()` rejects with `AbortError` identical to `signal.reason`; custom reason is passed through; `AbortSignal.timeout` gives `TimeoutError`; `AbortSignal.any`; `throwIfAborted`; body read after abort rejects `AbortError`. Race table (R 400 ms, RE 600 ms, REA 100 ms): naive hook ends on "re", ignore flag and abort end on "rea" (RTL with fake timers). Serial queue code keeps order and survives a rejection.
- Corrected: section 5.8 claimed the query library "discards the result for an unobserved or cancelled query". Executed against query-core 5.104: that is true for `cancelQueries` (entry reverts, late result discarded), but when the last observer unsubscribes and `queryFn` ignores `signal`, the request runs to completion and the result IS written to the cache. With a consumed signal, unsubscribing aborts. Text rewritten with the three observed cases.
- Added MDN support versions for `AbortSignal.timeout`/`any`/`throwIfAborted`; cited the useTransition caveat that updates after `await` need an extra `startTransition`.
- Unresolved: whether specific routers cancel loaders on navigation (left as "check your router version").
