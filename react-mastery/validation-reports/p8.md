## Most significant corrections (cross-cutting)

1. **Vitest fake timers + Testing Library hang (lessons 04, 03, 07, 16, 17, 02).** `userEvent.setup({ advanceTimers })` and `delay: null` are *not* enough under `vi.useFakeTimers()`: RTL's `asyncWrapper` (used by every `user.*`, `findBy*`, `waitFor`) ends with a real `setTimeout(0)` that is faked and only auto-advanced if a global `jest` exists (RTL `pure.js`, DTL `jestFakeTimersAreEnabled`). Reproduced: the lesson-04 SearchBox tests and the lesson-16 SearchBox test timed out at 5 s. Verified fixes: `vi.stubGlobal("jest", { advanceTimersByTime: vi.advanceTimersByTime.bind(vi) })`, `shouldAdvanceTime: true`, or faking only other timers. Examples and answers rewritten; table of variants added to lesson 04 §3.4.
2. **Vitest 3 + jsdom `AbortSignal` mismatch (lessons 06, 07, 08).** On Vitest 3.2.7 + jsdom 30, `fetch(url, { signal })` throws `TypeError: RequestInit: Expected signal ... AbortSignal`, which breaks TanStack Query (its `queryFn` signal) and React Router data routers. 9/21 of lesson-07's own example tests failed. **Not reproduced on Vitest 4.1.12 or 5.0.5.** `happy-dom` does not fix it on Vitest 3. Lesson text now says: use Vitest >= 4, or `// @vitest-environment node` for those files.
3. **`use(promise)` tests (lesson 04).** `render()` (sync act) around a suspending component never reveals the content (React warns "suspended inside an act scope, but the act call was not awaited"). Verified fix: `await act(async () => { render(...) })`. The lesson example was rewritten.
4. **Unawaited `expect(...).rejects/resolves` (lesson 02).** Not "silently passes" in Vitest 3.2.7 (auto-awaited with a warning, failures still fail); fails the test outright in Vitest 5.
5. **Playwright (lessons 09, 12, 15).** `reducedMotion` is not a top-level `use` key (use `contextOptions`); component-testing packages removed in 1.63; Docker tag is `-noble`; Node 18 is not supported (docs: 22/24/26); GitHub Action majors bumped.
6. **TypeScript example in lesson 11 failed to type-check** (`expectTypeOf(ok1.onChange)` is narrowed by assignment); fixed and both forms verified with `tsc --strict` and `vitest --typecheck`.
7. **New majors noted** (short notes, no rewrites): Vitest 4/5, MSW 3, React Router 8, TypeScript 6/7, ESLint 10, jest-dom 7, Playwright 1.64, Storybook 10.
